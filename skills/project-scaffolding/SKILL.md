# Project Scaffolding

## When to use this skill

When the user says `--yarat` and there is no existing project —
AIECP itself is the only thing in the zip/repo. This skill creates
the project skeleton from scratch before `project-onboarding` can
discover it.

## Procedure

### 1. Determine the project type

Ask the user (within question budget) or infer from the task:
- Language: TypeScript, Python, Go, Rust, Java, Swift, etc.
- Framework: React, Vue, Next.js, Express, FastAPI, Actix, etc.
- Platform: web, mobile, desktop, CLI, API, library
- Test runner: jest, vitest, pytest, cargo test, go test

### 2. Create directory structure

Based on the project type, create:

```
project-name/
├── src/                # source code
├── tests/              # test files
├── docs/               # documentation
├── .aiecp/             # AIECP artifacts (auto-created by discovery)
├── .aiecp-framework/   # AIECP framework (symlinked by init-aiecp.mjs)
├── AGENTS.md           # auto-generated by sync-entrypoints
├── CLAUDE.md           # auto-generated
├── package.json        # or pyproject.toml / Cargo.toml / go.mod
├── tsconfig.json       # if TypeScript
├── .gitignore
└── README.md
```

### 3. Generate config files

Create the appropriate manifest:
- **TypeScript:** `package.json` with scripts, `tsconfig.json`
- **Python:** `pyproject.toml` with poetry/setuptools, `pytest.ini`
- **Rust:** `Cargo.toml`
- **Go:** `go.mod`

Include test runner setup in the manifest.

### 4. Initialize git

```bash
git init
git add -A
git commit -m "Initial commit: project scaffold"
```

### 5. Run AIECP init

```bash
node .aiecp-framework/scripts/init-aiecp.mjs .
```

This runs discovery, generates entrypoints, and creates the
auto-activate marker.

### 6. Emit evidence

Emit a `Decision` with `what: "project_scaffolded"`, `why: "created
<language>/<framework> project with <test_runner>"`, `validated: true`.

## Tool integration

- `filesystem_write`: create directories and files
- `shell_exec`: run `git init`, `npm init`, `cargo init`, etc.
- `filesystem_read`: read AIECP framework files for reference

## Validation

Successful when:
- Project directory exists with valid manifest file
- `.aiecp/project-intelligence.json` exists (discovery ran)
- `AGENTS.md` exists (entrypoints generated)
- Git repository initialized with at least one commit

## Examples

**Happy path:** User says "repo-link --yarat e-commerce API with
Stripe payments". Skill determines: TypeScript + Express + PostgreSQL
+ jest. Creates directory structure, generates package.json with
dependencies, runs init-aiecp, emits Decision. Orchestrator then
takes over: specification -> implementation -> testing.

**Failure mode:** User's request is too vague ("--yarat something").
Skill asks one clarifying question within budget. If still ambiguous,
transitions to blocked with `on: project_type_ambiguous`.
